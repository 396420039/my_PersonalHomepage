`asyncio` 适合大量 I/O 等待：调用模型、访问数据库、请求第三方接口。事件循环在协程遇到 `await` 时切换任务，因此单线程也能维持较高并发。CPU 密集型解析、向量计算或图像处理仍会阻塞事件循环，应交给进程池、原生扩展或独立服务。

## 正确的并发边界

不要把所有函数机械地改成 `async def`。只有底层操作真正提供异步接口时，等待才会让出执行权。同步 SDK 包在异步函数里仍然会阻塞。

生产系统还需要限制并发。可以使用 `Semaphore` 控制同时请求模型的数量，使用有界队列形成背压，并为外部调用设置超时、重试和取消传播。`gather` 适合并行执行彼此独立的任务；任务存在先后依赖时，应保留清晰的顺序。

## 落地检查

1. 区分 I/O 密集与 CPU 密集任务。
2. 检查依赖库是否真正支持异步。
3. 为并发、队列长度和超时设置上限。
4. 记录任务耗时、取消、重试与异常。
